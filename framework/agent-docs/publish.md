# Deploy your documentation

**Updated: 2026-10-20.**

After the [quickstart](https://www.shoalrun.com/start.md), your documentation project has `@shoalrun/cli` installed. Run the commands below from that project directory, `my-docs/`.

## Prepare a release

Set `site.origin` in `docs.config.yaml` to your public HTTPS origin. Then audit the project and build it:

```sh
npx --no-install shoalrun audit docs.config.yaml
npx --no-install shoalrun build docs.config.yaml dist
```

Review the generated HTML, Markdown, and `dist/documents.json`. A build replaces its output directory; keep source files outside `dist/`. If it fails, use [troubleshooting](https://www.shoalrun.com/publish/troubleshooting.md).

## Choose a host

Choose a hosting route based on the artifacts and server features your site needs.

| Hosting route                                        | What to deploy                                                                                                                         |
| ---------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| [Vercel](https://www.shoalrun.com/publish/vercel.md) | The `.vercel/output/` bundle generated by the installed CLI.                                                                           |
| Node server                                          | The compiled site and the installed `@shoalrun/cli` package, as described below.                                                       |
| Another host                                         | The compiled files plus routing and headers implementing the [HTTP contract](https://www.shoalrun.com/publish/content-negotiation.md). |

For a site hosted at `/docs`, set `site.basePath: /docs`. The Node and Vercel adapters serve the prefixed routes directly. On a static host that mounts a directory at `/docs`, publish the build output's `docs/` subtree as that directory's root. The build keeps internal manifests at the output root for local commands. Static hosts also need routing rules for [Markdown content negotiation](https://www.shoalrun.com/publish/content-negotiation.md).

### Node hosting

On a machine with Node.js 22.12 or newer and npm, check out your documentation project with its `package.json` and lockfile. Configure package registry access as described in the [quickstart](https://www.shoalrun.com/start.md), then run these commands from the project directory:

```sh
npm ci
npx --no-install shoalrun build docs.config.yaml dist
npx --no-install shoalrun serve dist --host 0.0.0.0 --port 8080
```

The last command runs the server in the foreground. Configure your host's process manager to run it from the project directory and restart it after a release. Route your public HTTPS endpoint to port 8080 using the host's proxy or load balancer. Preserve request `Accept` headers and response headers through that proxy. The Node server handles HTML, negotiated Markdown, explicit `.md` URLs, and discovery resources.

For a local check, use `http://localhost:8080/install/` and `http://localhost:8080/install.md` from the minimal starter. Replace those paths with your own pages when you change the content.

### Other hosts

A static upload alone does not establish Markdown content negotiation. Configure the host to serve the resources and page variants described in [content negotiation](https://www.shoalrun.com/publish/content-negotiation.md), including `Vary: Accept`, content types, Markdown alternate links, redirects, and 404 responses. Use [generated outputs](https://www.shoalrun.com/publish/output.md) to identify the files to deploy.

## Verify the public site

Replace the example origin and page path below with a published page on your site:

```sh
curl -i -H 'Accept: text/html' https://your-docs.example/install/
curl -i -H 'Accept: text/markdown' https://your-docs.example/install/
curl -i https://your-docs.example/install.md
```

Confirm that all three requests return HTTP 200. The first should return HTML; the second and third should return the page as Markdown. Check the response headers and missing-page behavior against the [HTTP contract](https://www.shoalrun.com/publish/content-negotiation.md). A local build verifies files; these requests check the host's responses.

Shoalrun's docs repository also has a [whole-site deployment checker](https://www.shoalrun.com/publish/deployment-check.md). That repository script is separate from the installed CLI.

Before sharing a page, [check its SEO and social preview metadata](https://www.shoalrun.com/publish/seo.md), including the public share-image URL.

Next, [put multiple versions on one site](https://www.shoalrun.com/publish/publications.md) if you need several editions in one site. For branches, tags, and retained build snapshots, see [use Git branches for separate docs sites](https://www.shoalrun.com/publish/revisions.md).
