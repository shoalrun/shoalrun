Payments v3 separates request retries from business reconciliation. Use an idempotency key for retry safety and an order reference for settlement matching. Reporting can stay on v1 when Payments moves to v3.

## Create a payment

1. Generate an idempotency key for this payment attempt.
2. Send the order reference separately from the key.
3. Save the returned payment identifier and status.

```json
{
  "idempotencyKey": "payment-attempt-1042",
  "orderReference": "order-1042",
  "amount": { "value": 12500, "currency": "USD" }
}
```

## Retry a submission

Reuse the idempotency key for the same attempt. A new order needs a new key. Keep the order reference stable when comparing payment and settlement records.
