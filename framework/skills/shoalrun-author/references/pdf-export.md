# PDF export

For print design, brand styling, and visual verification, read the [PDF skill](../../shoalrun-pdf/SKILL.md). Its print reference and stylesheet starter accompany the instructions; keep the complete skill folder when installing it.

Check the installed CLI's `export --help` and supported output settings before configuring PDFs. Use `export --format pdf --document ID --out DIRECTORY` for one page; omit the document selector for a complete publication. Select exact product/channel/version/language coordinates when more than one publication is enabled. Pass the same customer profile as the site. PDF selection uses the target's contentFilter, otherwise the site's filter; ordinary HTML/Markdown application exports retain their independent filter behavior.

Set shared print settings under outputs.pdf and per-target overrides under exports.<target>.pdf. Local stylesheet/font/logo paths resolve relative to their declaring configuration. Register licensed local fonts explicitly; custom CSS cannot import files or load URLs. Body CSS doesn't style Chromium's separate header/footer templates. Their escaped text supports {title}, {page}, and {pages}. The TOC is linked without printed page numbers. Bookmarks/tagging need actual PDF inspection; don't infer accessibility certification.

The page action is disabled by default. An enabled outputs.html.pdf mapping defaults to mode:print for static sites: the browser creates a separate branded view and opens its print dialog, with no generated page PDFs or extra print documents. Configure its label, placement before/after Markdown actions, include/exclude IDs, and optional named style target. Shared outputs.pdf styling and assets serve all print views; only a target's PDF settings apply, never its content selection. Page frontmatter pdf:false suppresses the action. Native browser printing remains a fallback using website print CSS. Keep full-manual CLI export and its published download optional.

Explicit mode:endpoint prepares private inputs for on-demand generation through a Node host with Chromium. Optional style names an export target's pdf mapping; only its styling applies, never its page/publication/filter selection. Vercel supports browser printing and rejects endpoint mode. Never publish pdf-runtime.json or __shoalrun/pdf-data through a generic static server. A custom handler must use the same authentication boundary as the site. Audience/profile selection isn't visitor authorization.

Generation requires an installed Chrome/Chromium executable through SHOALRUN_PDF_BROWSER or outputs.pdf.executablePath. It runs offline with JavaScript disabled and the browser sandbox retained. Missing assets, remote images, missing browser, or rendering failures must be reported; don't substitute a print dialog for a promised PDF download. Preserve existing exports on failure.

Verify a page and full publication, their selection/order, excluded content, links, fonts, bookmarks, page breaks, long code/tables, and static component fallbacks. Inspect rendered PDF pages as well as extracted text. Keep PDF manifests separate from content REST representation manifests. Enabling an action doesn't authorize deploying internal/customer PDFs publicly.
